SPO6 Report

1. Работа с таймером
- В `spo6.target.pdsl` добавлены специальные регистры таймера и прерываний:
  - `timer`, `quantum`, `intvec`, `intr_enabled`, `intr_active`;
  - сохранённый interrupt-context `irq_ip`, `irq_sp`, `irq_bp`, `irq_dbp`, `irq_csp`;
  - отдельный kernel-context `ksp`, `kbp`, `kdbp`, `kcsp`.
- После каждой инструкции target уменьшает `timer`.
- При достижении `timer == 0` target:
  - сохраняет текущий контекст в `irq_*`;
  - переключает VM на kernel-context;
  - передаёт управление в handler по адресу `intvec`.
- Возврат из handler выполняется через `iret`, который восстанавливает сохранённый контекст и перезапускает таймер.

2. Переключение контекста CPU
- Реальное переключение контекста вынесено в:
  - target-level механизм сохранения `irq_*`;
  - handler `rt_timer_handler` в `tests/scheduler_demo.asm`;
  - процедуры `rt_save_irq_context` и `rt_load_irq_context`.
- PCB логического потока хранит:
  - реальные `ip/sp/bp/dbp/csp`;
  - `remaining`, `state`, `start_time`, `finish_time`;
  - логический `saved_pc` и `saved_acc` для контрольных вычислений.
- Для старта и завершения dispatch используются:
  - `rt_select_candidate`
  - `rt_activate_current`
  - `mark_dispatch`
  - `finish_task`
  - `execute_tick`

3. Алгоритмы планирования
- Реализованы отдельные процедуры планирования:
  - `enqueue_fcfs`
  - `pick_fcfs`
  - `select_spn`
- `FCFS`:
  - поступающие процессы помещаются в FIFO-очередь;
  - процесс выполняется до завершения;
  - следующий выбирается из головы очереди.
- `SPN`:
  - при освобождении CPU выбирается готовый процесс с минимальной длительностью;
  - при равенстве длительностей используется порядок поступления.
- Оба алгоритма невытесняющие, поэтому таймер вызывает планировщик каждый тик, но замена текущего потока происходит только после завершения.

4. Тестовая программа
- Файл: `tests/scheduler_demo.asm`
- Нагрузка:
  - arrivals: `0 3 6 9 12 15`
  - bursts: `4 4 7 7 4 4`
- Диапазон длительностей соблюдён: все задачи лежат в интервале `3..7`.
- Среднее время между поступлениями равно `3`.
- Каждая логическая задача представлена отдельным кодовым фрагментом на target VM.
- Тик таймера равен одному выполненному instruction-step пользовательского потока.
